# 素材生成成本与积分兑换比例规则

> 目标：让「用户付的积分」覆盖「供应商实付成本」，避免视频 / 代理模型把图片积分的利润吃光。  
> 口径日期：2026-09-19。供应商牌价会变，本表按当时公开价测算，落地前应用控制台账单复核。  
> **2026-09-19 已落地**：`lib/canvas/pricing.ts`、画布 `estimateNodeCost`、工作台生图扣费、独立套餐页 `/pricing`。

---

## 1. 结论先看

当前实现是**按节点类型收固定积分**，不看模型、时长、分辨率、供应商：

| 能力 | 现行扣积分 | 典型供应商成本 | 成本相对 Seedream 4.5 |
| --- | ---: | ---: | ---: |
| 文生图（Seedream 4.5） | 1 | ¥0.25 / 张 | 1× |
| 文生图（GPT-Image / Nano Banana Pro） | 1 | 约 ¥0.5–1.3 / 张 | 2–5× |
| 分镜 / 润色 / 提示词优化 | 1 | 约 ¥0.002–0.02 / 次 | 可忽略 |
| 音频（Suno，302.ai） | 1 | 约 ¥0.7–1.1 / 次 | 3–4× |
| 视频（默认 Seedance 2.0 Fast 5s 720p） | 3 | 约 ¥5.1 / 条 | **20×** |
| 视频（同模型 15s 720p） | 3 | 约 ¥15 / 条 | **60×** |

图片 1 积分、视频 3 积分，表面上是 1:3，真实成本大约是 **1:20 到 1:60**。这就是「成本和积分不成正比」的根因。

**不亏损的充要条件：**

```
用户支付金额 ≥ 供应商成本 × 安全系数
```

换算成积分：

```
扣积分 = max(1, ceil(供应商成本(元) × 安全系数 / 积分售价(元)))
```

建议默认：

- **积分售价**：1 积分 = **¥0.50**（用户侧）
- **安全系数**：图片 **2.0**（目标毛利率 50%）；视频 / 音频 **2.5**（覆盖 302 加价、时长波动、失败重试、OSS）
- **保底**：任何成功调用模型的动作至少扣 **1** 积分

按这套公式，默认 5 秒 720p Fast 视频应扣 **约 26 积分**，而不是 3。

## 2. 现行规则（代码事实）

### 2.1 积分从哪来

| 来源 | 数量 | 代码位置 | 说明 |
| --- | ---: | --- | --- |
| 新用户注册赠送 | +3 | `models/user.ts` | `TransactionType.gift` |
| 兑换码 | +10 | `models/redeem-code.ts` | 固定 10 积分 |
| 付费充值 | 未上线 | 仅有 `CheckoutSchema`（`credits` / `amount` / `monthly\|one-time`） | **没有实际兑换比例** |
| 失败退还 | 预扣差额 | `models/canvas.ts` `finalizeExecutionIfDone` | 成功步骤实扣，其余 `refund` |

当前产品几乎只靠赠送积分运转。上线售卖前必须先定「1 积分值多少钱」，否则无法判断亏不亏。

### 2.2 积分扣在哪

| 场景 | 扣积分 | 是否区分模型 / 参数 | 实现 |
| --- | ---: | --- | --- |
| 工作台壁纸生成 | 1 | 否（Seedream / GPT / Gemini 同价） | `consumeCreditsAndSaveWallpaper` |
| 工作台提示词优化 | 1 | 否 | `consumeCreditsAndSavePromptOptimization` |
| 画布文本 AI 润色 | 1（`POLISH_TEXT_COST`） | 否 | `app/api/protected/canvas/polish-text/route.ts` |
| 画布图像节点 | `baseCost = 1` | 否 | `estimateNodeCost` |
| 画布分镜节点 | `baseCost = 1` | 否 | 同上 |
| 画布视频节点 | `baseCost = 3` | 否（4–15 秒、480p/720p/1080p、四款模型同价） | 同上 |
| 画布音频节点 | `baseCost = 1` | 否（Suno v4–v5.5 同价） | 同上 |
| 文本 / 上传节点 | 0 | — | 不调用模型 |
| 保存到工作台 | 0 | — | 只拷贝已生成文件 |

画布计价入口：

```282:286:lib/canvas/registry.ts
export function estimateNodeCost(type: CanvasNodeType, config?: CanvasNodeConfig): number {
  const def = NODE_TYPE_DEFS[type];
  if (!def.executable) return 0;
  return def.baseCost;
}
```

`config` 传入了但没用。预扣（estimate）和结算（capture）共用这个函数，所以**时长变长、换成更贵的模型，积分也不会变**。

### 2.3 画布账本机制（这部分是对的）

1. 运行前按计划总和预扣 `reserved_credits`。
2. 步骤成功才写入 `credits_consumed`。
3. 执行终态释放 `reserved - captured`（`refund`）。
4. 供应商失败、取消，未成功步骤不实扣。

亏损不来自退款逻辑，而来自**报价本身远低于供应商账单**。

| GPT-Image 2K | ¥1.20 | ¥0.50 | **−58%** | 亏损 |
| Suno | ¥0.90 | ¥0.50 | **−44%** | 亏损 |
| 分镜 | ¥0.02 | ¥0.50 | 很高 | 不亏 |
| 视频 5s Fast 720p | ¥5.10 | ¥1.50 | **−71%** | 严重亏损 |

一条「分镜 + 9 张 Seedream + 1 条 15s 视频 + 1 首 Suno」的画布：

- 现行扣分：1 + 9 + 3 + 1 = **14 积分** → 收入 ¥7.00  
- 供应商成本：0.02 + 2.25 + 15.30 + 0.90 ≈ **¥18.5**  
- 净亏约 **¥11.5 / 次**

视频是亏损放大器。图片里只有 Seedream 4.x 在 1 积分下勉强打平；代理模型已经在贴钱。

## 5. 兑换比例规则（建议作为计费宪法）

### 规则 1 — 先定积分锚，再定扣分表

```
积分售价 V（元/积分）= 充值金额 / 到账积分
```

推荐锚：**V = 0.50 元/积分**。

建议充值档（可再加赠，加赠会降低 V，必须重新验算）：

| 档位 | 用户实付 | 到账积分 | 实际 V | 是否允许 |
| --- | ---: | ---: | ---: | --- |
| 体验 | ¥10 | 20 | 0.50 | 是 |
| 标准 | ¥50 | 100 | 0.50 | 是 |
| 大额 | ¥100 | 220（+10%） | 0.45 | 仅当扣分表按 V=0.45 重算后仍 ≥ 安全线 |
| 兑换码 | ¥0 | 10 | 0 | 营销成本，单独预算，不摊进单价 |
| 新用户 | ¥0 | 3 | 0 | 同上，限制不能生成视频或给试用配额 |

加赠超过 10% 后，等于所有生成的保本积分要同比上调。

### 规则 2 — 扣分只认成功产出，报价必须覆盖最坏成功档

```
扣分 = max(最低积分, ceil(K × S / V))
```

| 符号 | 含义 | 建议值 |
| --- | --- | --- |
| `K` | 该次调用的供应商成本（元） | 用 302/方舟**当前渠道**价，不用官网折扣价 |
| `S` | 安全系数 | 图片 2.0；视频/音频 2.5；文本 不按公式，固定 1 |
| `V` | 积分售价 | 0.50 |
| 最低积分 | 成功调用的下限 | 1 |

`K` 必须按**实际执行配置**取：模型、分辨率、时长、1K/2K、是否含参考视频。禁止只按节点类型。

### 规则 3 — 视频按「秒 × 档位单价」

```
视频积分 = max(3, ceil(每秒成本 × 秒数 × 2.5 / 0.50))
```

保留最低 3 积分，避免 480p 短视频被低估到和文本一样。

按 V=0.50、S=2.5 的建议表（302 口径，无参考视频）：

| 模型 | 分辨率 | 每秒成本约 | 5 秒积分 | 10 秒积分 | 15 秒积分 |
| --- | --- | ---: | ---: | ---: | ---: |
| Seedance 2.0 Fast | 480p | ¥0.54 | 14 | 27 | 41 |
| Seedance 2.0 Fast | 720p | ¥1.02 | **26** | **51** | **77** |
| Seedance 2.0 | 720p | ¥1.24 | 31 | 62 | 93 |
| Seedance 2.0 | 1080p | ¥2.78 | 70 | 139 | 209 |
| Seedance 1.0 Pro | 1080p | ¥0.78 | 20 | 39 | —（上限 12s ≈ 47） |
| Seedance 1.0 Lite | 1080p | ¥0.53 | 14 | 27 | — |

含参考视频时 2.0 系列 token 单价下降，但输入时长计入用量，短参考不一定更便宜。上线后用 `usage.completion_tokens` 校准，未校准前按「不含视频」档报价，避免低估。

### 规则 4 — 图片按模型（和分辨率）分档，不再全部 1 积分

V=0.50、S=2.0：

| 模型 | K | 建议积分 | 收入 | 毛利率 |
| --- | ---: | ---: | ---: | ---: |
| Seedream 4.0 | 0.20 | **1** | 0.50 | 60% |
| Seedream 4.5（默认） | 0.25 | **1** | 0.50 | 50% |
| Seedream 3.0 | 0.20 | **1** | 0.50 | ~60% |
| Nano Banana 2 1K | 0.51 | **3** | 1.50 | 66% |
| Nano Banana 2 2K | 0.77 | **4** | 2.00 | 62% |
| Nano Banana Pro | 1.10 | **5** | 2.50 | 56% |
| GPT-Image-2 1K | 0.60（取中高档） | **3** | 1.50 | 60% |
| GPT-Image-2 2K | 1.20 | **5** | 2.50 | 52% |

工作台壁纸必须与画布图像**共用这张表**，不能继续「壁纸永远 1 积分」。

### 规则 5 — 音频按次，不按模型版本打折

Suno 各版本 302 侧基本按次，取 K=¥1.10（偏保守）：

```
音频积分 = ceil(1.10 × 2.5 / 0.50) = 6
```

建议 **6 积分 / 次**。若后续确认稳定为 $0.10 且无 timing 附加费，可降到 4。在账单验证前不要低于 4。

### 规则 6 — 文本类固定 1 积分

分镜、润色、提示词优化继续 1 积分。成本可忽略，1 积分当作最低服务费和滥用门槛。不要为了「更正比」改成 0，否则会被刷。

### 规则 7 — 预扣按上限，结算按成功；失败不把供应商损失转嫁用户（产品已如此）

供应商已扣费但平台判定失败（超时后实际出片、审核失败但渠道仍计费）记入**运营损耗**，用安全系数覆盖，不在用户侧追加扣费。损耗超过安全系数时，应提高 S 或下线该模型。

### 规则 8 — 四舍不入，只进位

`ceil`，禁止四舍五入。¥5.1 × 2.5 / 0.50 = 25.5 → **26**，不能收 25。

### 规则 9 — 价格版本冻结在执行快照里

技术方案已要求运行时冻结成本报价。扣分表要带 `price_version`（例如 `2026-09-19`）。已预扣的执行仍按快照结算，中途改价不影响进行中的任务。

### 规则 10 — 赠送积分与付费积分分账（可选但建议）

赠送积分用于图片 / 文本；视频、Suno、GPT/Gemini 要求付费积分或单独试用次数。否则 3 点新用户积分一旦能跑视频，会直接打穿成本。

## 7. 若暂时不能改扣分：至少做的止损

若短期必须维持「图 1 / 视频 3 / 音频 1」的产品体验，则**只能改售价或关能力**，否则必亏：

1. **下线或隐藏** Seedance 2.0 标准 1080p、15 秒档、GPT-Image 2K、Nano Banana Pro。  
2. 视频默认锁 **Fast + 720p + ≤5 秒**。  
3. 1 积分售价至少 **¥1.70** 才能打平 5 秒 Fast 720p；要覆盖 15 秒必须 **¥5.10 / 积分**。这个售价会让 Seedream 图变得极贵（1 张图用户付 ¥1.7–5.1），体验更差。  
4. 因此「不改扣分、只涨积分售价」不是好方案。**优先改扣分表。**

## 8. 实现要点（改代码时）

1. 把 `NODE_TYPE_DEFS.*.baseCost` 从「展示用基准」改成「最低档展示」；真正扣费全部走 `estimateNodeCost(type, config)`。  
2. `estimateNodeCost` 必须读取 `config.model`、`config.duration`、`config.resolution`（视频）、图片 `resolution`（1k/2k）。  
3. 工作台 `gen-wallpaper` / `optimize-prompt` 不要写死 `-1`，复用同一张价格表。  
4. 价格表建议进数据库或独立 `lib/canvas/pricing.ts`，带版本号；与技术方案「Model Registry 含价格」对齐。  
5. 视频用 `clampVideoDuration` / `clampVideoResolution` 之后的值计价，避免按 1080p 报价却按 720p 生成（或反过来）。
